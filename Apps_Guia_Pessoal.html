📖 Mapa do Atelier

Guia para leigos — descubra rapidinho qual arquivo abrir quando quiser mudar algo, e o que pedir para uma IA.

🔗 Ordem de carregamento (NÃO mude)

Os 4 arquivos carregam nesta ordem. Se trocar dois de lugar, o app abre em branco ou com erro no console.

1. estado.js → 2. logica.js → 3. interface.js → 4. app.js
Por quê? Cada arquivo usa coisas do anterior. logica.js precisa do S (definido em estado.js). interface.js usa as funções do logica.js. E o app.js liga tudo no final com init().
⚠️ Regra de ouro: sempre que você editar qualquer arquivo, teste com Ctrl+Shift+R (hard reload) e, se for PWA instalado, desregistre o service worker em DevTools → Application → Service Workers → Unregister. Senão você continua vendo a versão antiga em cache.

📁 Detalhe de cada arquivo

1. estado.js — a memória 🧠

"Onde o app guarda as coisas que ele sabe."

O que tem dentro

  • THEMES — todas as paletas de cor
  • CAT_PRO / CAT_PERSONAL — categorias de contato
  • TASK_TYPES — tipos de tarefa do dropdown
  • S — o "estado global" (tarefas, contatos, timer, etc.)
  • save() / load() — gravam e leem do localStorage
  • exportData() / importData() — backup em JSON
  • Modelo de tarefa (formato dos objetos)

O que é seguro mexer

  • Adicionar/remover cor em THEMES
  • Adicionar categoria em CAT_PRO ou CAT_PERSONAL
  • Adicionar/remover item em TASK_TYPES
  • Ajustar nome de chave em exportData/importData (⚠️ cuidado: pode quebrar backups antigos)

❌ NÃO mexer sem saber

  • A estrutura de S (os nomes das chaves usadas em todo lugar)
  • A lógica de save() / load()

Prompt pronto para IA

No arquivo estado.js do meu app, adicione um novo tema chamado "Vinho" em THEMES com as cores: fundo #1a0f12, texto #f0e6e8, destaque #c25a6a. Mantenha o formato dos outros temas.

2. logica.js — o cérebro ⚙️

"Onde ficam as regras. Não desenha nada — só calcula."

O que tem dentro

  • taskBaseXp / xpToNextLevel — ganho de XP e progressão
  • computeTaskScore — nota de prioridade das tarefas
  • computeContactScore — nota de relacionamento dos contatos
  • updateJobNextFollowUp — quando lembrar de dar follow-up
  • tickTimer / formatTime — o cronômetro
  • computeJobScore — nota de vagas

O que é seguro mexer

  • Números de XP (ex: dar mais XP para tarefas difíceis)
  • Pesos dos scores (o que vale mais ponto)
  • Dias do follow-up (7 em vez de 14, por exemplo)

❌ NÃO mexer sem saber

  • A assinatura das funções (nomes e parâmetros) — interface.js e app.js chamam elas
  • A lógica de tickTimer (mexer pode travar o timer)

Prompt pronto para IA

No arquivo logica.js do meu app, na função computeTaskScore, quero que tarefas com prazo HOJE ganhem +30 pontos e tarefas atrasadas +50. Me mostre só o trecho alterado, não o arquivo inteiro.

3. interface.js — o desenho 🎨

"Onde o HTML é gerado. Mexer aqui muda o que você vê."

O que tem dentro

  • viewWeek, viewStats, viewTasks… — cada aba
  • cardTask, cardContact, cardJob — cada cartão
  • Modais (openModal…) — janelas que abrem
  • toast — a mensagem que aparece rapidinho
  • renderFocus — modo foco
  • openSearch — painel Ctrl+K

O que é seguro mexer

  • Textos que aparecem na tela (labels, botões)
  • Ordem dos elementos dentro de um card
  • Adicionar um emoji/ícone novo
  • Trocar classes CSS (se você tiver a classe no seu CSS)

❌ NÃO mexer sem saber

  • Nomes de id="" e data-a="" — o app.js usa eles para escutar cliques
  • escapeHtml ou similar (proteção contra HTML malicioso)
  • Chamadas para funções do logica.js

Prompt pronto para IA

No arquivo interface.js do meu app, na função cardTask, adicione uma etiqueta "🔥 Urgente" no topo quando a tarefa tiver prazo hoje. Use a classe CSS existente .badge se houver; senão, apenas um span com estilo inline. Me mostre só o trecho alterado.

4. app.js — o maestro 🎼

"Liga tudo: escuta cliques, teclas, roda o init e registra o Service Worker."

O que tem dentro

  • init() — o que roda quando o app abre
  • Listener de click com o switch gigante de ações (data-a)
  • Listener de keydown (atalhos de teclado)
  • Listener de input/change (formulários)
  • Registro do Service Worker (PWA / offline)
  • Configuração do FAB (botão flutuante)

O que é seguro mexer

  • Adicionar um atalho novo no keydown
  • Adicionar um case novo no switch de ações
  • Adicionar item no menu do FAB
  • Adicionar uma chamada no fim do init()

❌ NÃO mexer sem saber

  • Ordem do init() (se inverter, algo fica undefined)
  • Registro do Service Worker
  • O switch que já existe — só adicione casos novos, não remova

Prompt pronto para IA

No arquivo app.js do meu app, adicione um atalho Ctrl+N que chama a função openModalNewTask() (já existe). Coloque junto aos outros atalhos no listener keydown. Me mostre só o trecho alterado.

✅ Checklist após QUALQUER alteração

  1. Salve o arquivo editado.
  2. No navegador, abra com Ctrl+Shift+R (hard reload) para limpar cache.
  3. Abra o console (F12 → Console) e veja se não há texto vermelho (Uncaught ReferenceError = algo não foi definido).
  4. Se você usa como PWA instalado: DevTools → Application → Service Workers → Unregister e recarregue.
  5. Teste o fluxo que você mexeu: abriu a aba? o botão funciona? o dado salva?
  6. Se mexeu em estado.js: recarregue a página e veja se os dados continuam lá (persistência).
  7. Se mexeu no service-worker.js: bump o CACHE_VERSION (ex: v3 → v4) senão ninguém recebe a atualização.
  8. Faça um backup antes de mexer: Application → Local Storage → copie o conteúdo, ou exporte pelo próprio app.
⚠️ Antes de qualquer mudança grande: exporte o backup do app (se ele tem botão de export) OU copie o conteúdo do localStorage em DevTools → Application → Local Storage. Se der ruim, é só importar de volta.
